# 最佳实践

以下是一些推荐的做法，帮助您更好地使用 test-docs。

## 内容组织

- **按主题划分目录**：将相关的文档放在同一分类下（如 `guide/`、`api/`），方便读者按板块查找。
- **保持单一来源**：同一概念只在一个地方详细说明，其它页面通过链接引用，避免内容重复与不一致。
- **控制单页篇幅**：较长的内容拆分成多个页面，配合 `sidebar_position` 控制阅读顺序，避免单页过长。

## 写作规范

- **标题层级清晰**：一篇文档只使用一个一级标题，其余按 `##`、`###` 逐级展开。
- **代码示例可运行**：粘贴的代码块尽量注明运行环境与前置依赖，方便读者直接复现。
- **参数与示例并重**：涉及命令、配置或 API 时，既说明各参数含义，也给出完整示例。

## 维护建议

- **及时更新**：当功能或配置发生变化时，同步更新对应文档，避免文档与实际行为脱节。
- **善用版本化**：对于有版本差异的内容，可利用 Docusaurus 的版本化功能归档旧版文档。
- **定期检查链接**：新增或移动页面后，确认站内链接仍然有效，可借助 `onBrokenLinks` 在构建期发现失效链接。
